Camera System

One of my main tasks within the project was to design and develop an advanced system of fixed and semi-fixed cameras that provides an immersive and dynamic visual experience. This system was implemented to suit the narrative and gameplay needs, allowing precise control over perspective and framing in each scenario of the game.

In addition, I developed a complementary system for cinematics, focused on highlighting dramatic moments in the game, such as the deaths of the main character or bosses. This system allowed the playback of predefined sequences that integrate smooth transitions, zooms and dramatic angles, ensuring that each key scene was impactful and memorable.

Going into more detail on the camera system. A system has been designed to control where the cameras go by means of empty points in the world. These points are related to a collision volume that represents the room you are in. Once you enter one of these volumes the camera transitions according to defined parameters. 

  • class ACameraPoint : public AActor
{
    UCameraComponent* CameraComponent;               /**  Unreal Camera Component */
    USplineComponent* SplineComponent;               /**  The spline through which the camera will move */

    ELookMode LookMode;                              /**  Behaviour of where the camera will look */
    bool bFollowSpline;                              /**  If the camera moves along the spline or not */
    FCameraTransitionParams DefaultTransitionParams; /**  The transition params used by default */

    ...

    /** The parameters to be used for the transition to the camera as key  */
    TMap<ACameraPoint*, FCameraTransitionParams> OverridenTransitionParams;
};

This object represents the camera and has different variables to control its behaviour, both in terms of movement and view.

In terms of the behaviour of where the camera looks we have the variable LookMode where thanks to an enum that defines where the camera is going to look. As for example: It doesn't look at any, it looks at the player or it looks where the player is looking. In addition to this there is a variable bFollowSpline where you can set whether the camera is still or moves along the spline.

Finally, this object contains a series of variables to store the transition parameters between cameras. These parameters are differentiated in two. The default parameters which are used if there is no specific parameter for the camera to be transitioned. Or a map where as a key is used the camera to be transitioned to and as a value the parameters that will replace the default parameters.

The transition parameters are stored in a structure similar to this one: 

  • struct CameraTransitionParams
{
    float TransitionTime;               /** Duration of the transition */
    CameraBlendFunction BlendFunction;  /** Blend Function */
    bool bFade;                         /** Enable and Disable Fade */
    float FadeTime;                     /** Full Fade time */
    float FadeOutTime;                  /** Fade out time */
    float FadeInTime;                   /** Fade in time */
};

Estos parametros de transicion permite hacer transiciones instantaneas o con una interpolacion en un tiempo. Esta inerpolacion se biene definida por una funcion a elecion mediante un el enum CameraBlendFunction. Por ultimo se define si la camara tiene que hacer un fade a negro. Donde se puede contolar cuanto tiempo tarda en hacerse el fade.

Artificial Intelligence

In this project, I was in charge of developing the artificial intelligence (AI) of one of the game's bosses. For this, I worked closely with a member of the game design team, ensuring that the AI mechanics aligned with the desired gameplay experience.

Main features

The boss's AI has a perception system that reacts to two key senses:

  • Sight: Detects the player when he is within his field of vision.
  • Hearing: Responds to sounds triggered by the player, such as footsteps or interactions with the environment.

AI states

The AI operates through three main states, defined to provide a challenging and consistent gaming experience:

1. Patrolling:

  • The boss moves along a predefined route of points within the room.
  • This state is the initial behaviour when there is no indication of the player's presence.

2. Search:

  • When the boss detects suspicious activity (such as a noise or the player's last visible position), it enters this state.
  • In this mode, it actively searches for the player in the area near the event.

3. Pursue/Attack:

  • If the boss has direct visual contact with the player, it chases him and tries to close the distance to attack him.
  • This state prioritises offensive actions, increasing the tension in the confrontation.

Special behaviour

Upon completing the puzzle associated with the boss room, the boss moves towards a mirror and turns to stone, becoming immobilised. Once this happens, the player can pick up a key carried by the boss, which is needed to progress through the game.
